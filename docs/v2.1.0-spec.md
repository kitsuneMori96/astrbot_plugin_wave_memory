# WaveMemory v2.1.0 Spec — 数据治理 + 黑话升级 + 记忆精细化

## 目标

修正 v2.0 遗留的数据污染问题，升级黑话学习质量，加入 facts 衰减和数据备份。

---

## 批次 1：数据正确性（🔴 必做）

### 1.1 bot_id 统一为 db_id

**现状**：`beliefs` 表 `bot_id` 字段存的是 QQ 号（如 "2500447291"），来自 `soul_bot.qq_id`。
但 user_profiles 表用的是 db_id（如 "yushu"），历史数据还有 "1336495069"、"626751255" 混用。

**改动**：
- `main.py` 行 ~790：`soul_bot_id` 改用 `soul_bot.db_id`（从 BotProfile 取）
- 迁移脚本：`UPDATE beliefs SET bot_id = 'yushu' WHERE bot_id IN ('2500447291','1336495069','626751255')`
- 所有引用 `soul_bot_id` 或 `bot_id` 的地方 grep 确认一致

**文件**：`main.py`, `engine/db/belief_repo.py`, 迁移脚本

### 1.2 consolidation 排除 bot 自我 facts

**现状**：`services/consolidation.py` `_write_facts()` 中 LLM 提取 facts 时，如果对话中提到 bot 名字，会把 bot 写成 subject（如 `subject="626751255", predicate="说", object="我觉得..."` ），导致 328 条自我污染。

**改动**：
- `_write_facts()` 中 `_resolve_to_qq(subject)` 之后加判断：
  ```python
  # 排除 bot 自己作为 subject
  bot_ids = {self._bot_qq, self._bot_db_id, ...bot_aliases}
  if resolved_subject in bot_ids:
      continue  # 跳过这条 fact
  ```
- bot 标识列表从 `bot_registry` 获取（QQ号 + db_id + display_name）

**文件**：`services/consolidation.py`

### 1.3 清理存量脏数据

**迁移脚本执行**：
```sql
-- 删除 bot 自我 facts（subject = bot 的 QQ 号或名字）
DELETE FROM facts WHERE subject IN ('626751255','2500447291','1336495069','羽书','白泽');

-- bot_id 统一
UPDATE beliefs SET bot_id = 'yushu' WHERE bot_id IN ('2500447291','1336495069','626751255');
UPDATE beliefs SET bot_id = 'baizz' WHERE bot_id IN ('其他bot的QQ号');
```

**文件**：新建 `engine/db/migrations/v2_1_cleanup.py`

### 1.4 早期互动计数清零

**现状**：user_profiles 的 `interaction_count` 包含大量早期脏数据（seifer=773），v2.0 改为 on_bot_sent +1 但旧值未清。

**改动**：迁移时重置所有 interaction_count = 0，让 v2.0 逻辑重新累积。
```sql
UPDATE user_profiles SET interaction_count = 0;
```

## 批次 2：黑话学习升级（🟡）

### 2.1 递进重推机制

**现状**：`service.py` mine() 中，已存在 DB 的词只 `UPDATE frequency`，不重推含义。
第一次上下文不够 → no_info → 永远学不到。

**改动**：
- `jargon` 表新增字段：`last_infer_freq INTEGER DEFAULT 0`（上次推断时的频次）
- mine() 中判断：若 `current_freq` 跨过了下一个阈值 → 触发重推
- 阈值列表配置化：`jargon_inference_thresholds = [3,6,10,20,40,60,100]`
- no_info 的词不标记为"非黑话"，保留 `is_jargon = NULL` 等下次

**文件**：`services/jargon/service.py`, `engine/db/jargon_repo.py`（schema）

### 2.2 上下文条数放开

**现状**：
- `inference.py:82` `contexts[:5]` — LLM 推断只给 5 条
- `statistical_filter.py:68` 保留上限 5 条

**改动**：
- 配置项 `jargon_max_context`（默认 15）控制推断时给 LLM 的条数
- 配置项 `jargon_context_keep`（默认 10）控制内存保留上限
- inference.py 改为 `contexts[:self._max_context]`

**文件**：`services/jargon/inference.py`, `services/jargon/statistical_filter.py`

### 2.3 LLM 候选验证（可选开关）

**现状**：纯统计词频选候选，噪声多。

**改动**：
- 新增配置项 `jargon_llm_validate = false`
- 开启后：统计出 top_k 候选 → 用 LLM 批量验证哪些真是黑话
- validate prompt 参考 self_learning 的模板（群聊片段 + 候选列表 → 过滤）
- 关闭则退回纯统计（省 token）

**文件**：`services/jargon/service.py`, `services/jargon/inference.py`

### 2.4 全部参数配置化

新增到 `_conf_schema.json` 的 `Jargon_Settings`：

| 配置项 | 类型 | 默认 | 说明 |
|--------|------|------|------|
| `min_messages` | int | 10 | 触发挖掘的最小消息数 |
| `mine_cooldown` | int | 20 | 挖掘冷却秒数 |
| `top_k` | int | 20 | 每次挖掘取前 N 候选 |
| `max_context` | int | 15 | 推断时给 LLM 的上下文条数 |
| `context_keep` | int | 10 | 内存保留上下文条数 |
| `window_days` | int | 7 | 统计窗口天数 |
| `jieba_threshold` | int | 100 | jieba 词频阈值（>此值视为常用词） |
| `inference_thresholds` | string | "3,6,10,20,40,60,100" | 递进推断频次阈值 |
| `llm_validate` | bool | false | 开启 LLM 批量验证 |
| `weight_idf` | float | 0.4 | IDF 权重 |
| `weight_burst` | float | 0.3 | Burst 权重 |
| `weight_concentration` | float | 0.3 | 用户集中度权重 |

**文件**：`_conf_schema.json`, `services/jargon/service.py`

## 批次 3：记忆精细度（🟡）

### 3.1 facts 原子化衰减

**现状**：facts 表无 `last_reinforced`，`valid_from` 仅在重复写入时更新。
所有 facts 永远"新鲜"，不会淡出。

**改动**：
- facts 表新增字段：`last_reinforced REAL DEFAULT (created_at)`
- consolidation `_write_facts()` 中，重复 fact 写入时更新 `last_reinforced = now`
- 检索 facts 时加衰减权重：
  ```python
  age_days = (now - last_reinforced) / 86400
  decay = max(0.1, 1.0 - age_days * decay_rate)  # decay_rate 配置
  effective_confidence = confidence * decay
  ```
- 默认 `facts_decay_rate = 0.005`（200 天衰减到 0）
- 衰减只影响检索排序，不删除数据

**文件**：`engine/db/knowledge_repo.py`, `services/consolidation.py`, 新增配置项

## 批次 4：可靠性（🟡）

### 4.1 启动自动备份

**现状**：完全没有备份逻辑。docker restart 有数据风险。

**改动**：
- `main.py` initialize() 中，DB 打开前执行备份：
  ```python
  import shutil
  backup_dir = data_dir / "backups"
  backup_dir.mkdir(exist_ok=True)
  # 备份当前 DB
  timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
  shutil.copy2(db_path, backup_dir / f"wave_memory_{timestamp}.db")
  # 保留最近 N 个
  backups = sorted(backup_dir.glob("wave_memory_*.db"))
  for old in backups[:-max_backups]:
      old.unlink()
  ```
- 新增配置项 `backup_max_count = 5`
- 迁移失败自动回滚（用最新备份恢复）

**文件**：`main.py`

## 执行顺序

```
批次 1（数据正确性）→ 批次 4（备份）→ 批次 2（黑话）→ 批次 3（facts 衰减）
```

理由：先修数据 → 加备份保底 → 再改功能逻辑
