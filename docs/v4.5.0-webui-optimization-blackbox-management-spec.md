# v4.5.0 WebUI Optimization / Blackbox Management Spec

v4.5.0 聚焦 React WebUI 产品优化与黑盒能力管理前端补齐。它不重复做注入观测台的底层 trace，而是补齐“后端能力本体如何管理”的页面和入口。

## 1. 版本边界

前置版本：

- v4.3.0 完成 Jargon / Holyman / 注入治理。
- v4.4.0 完成神经云图与高级检索拆分实验台。

本版本处理：

1. 总览仪表盘、记忆管理器、智能导入、注入观测台、通道热配置的体验优化。
2. 维护工作台说明、任务、配置、事件、危险区重做。
3. 缺失黑盒管理前端补齐：不止 BookLore / FewShot，还包括 Facts、PersonRegistry/UserProfile/Affinity、FTS5、索引健康、学习对象等。
4. 配置来源、影响范围、风险等级统一标识。
5. 页面之间建立跳转闭环：总览发现问题 -> 管理页处理 -> 注入观测台验证 -> 通道配置调参。

本版本不处理：

- 不重写高级检索算法；高级检索实验台属于 v4.4.0。
- 不重写 AstrBot 6185 静态配置页。
- 不改变数据库主架构，除非为管理页提供必要的只读/轻量 CRUD API。
- 不把 trace 观测台重新发明一遍。
- 不直接改运行时目录代码。

### 2.3 主要问题

1. 页面已有，但缺少“下一步动作”：总览发现异常后不知道去哪里处理。
2. 注入观测台已有 trace，但缺少和各管理页的双向链接。
3. 通道热配置能调参数，但缺少通道说明、影响范围、配置来源、风险等级。
4. 记忆管理器混合了 live、book_lore、fewshot、bzz_experience 等 source，但没有资产类型语义。
5. 智能导入把静态 provider 配置、导入任务、Tag 提取任务混在同一页。
6. 维护工具仍是静态 `/maintain`，说明不足，审计策略、任务状态、风险边界不清。
7. 黑盒管理缺失不止 BookLore/FewShot，还包括 Facts、人物/关系、索引、FTS5、学习对象、灵魂引擎内部状态。

## 3. v4.5.0 目标

1. 建立 WebUI 的“发现 -> 管理 -> 验证 -> 调参”闭环。
2. 总览仪表盘从状态看板升级为行动入口。
3. 记忆管理器从普通列表升级为 source-aware 的资产浏览器。
4. 智能导入从任务按钮升级为导入向导和任务控制台。
5. 注入观测台保持 trace 定位，但优化筛选、详情阅读和跳转。
6. 通道热配置标清配置来源、影响范围、风险等级和通道语义。
7. 维护工作台补齐说明、任务、配置、事件、危险区。
8. 新增黑盒管理前端矩阵，优先补齐缺管理页的后端能力。

## 4. 非目标

- 不做新的注入 trace 存储模型。
- 不把所有管理页一次性做成复杂 CRUD；允许分阶段先只读、再有限编辑。
- 不把 BookLore 当作普通聊天记忆。
- 不把 FewShot 当作事实记忆。
- 不让用户在 UI 中关闭 safety channel。
- 不删除历史数据；破坏性操作必须二次确认。

## 6. 配置标识规范

所有配置块必须显示以下 badge 中的至少一个：

| Badge | 含义 |
|---|---|
| `静态配置` | 来自 AstrBot config.json，通常重启生效 |
| `热参数` | WaveMemory WebUI 可热更新 |
| `通道配置` | 影响注入通道启用、优先级、预算 |
| `治理配置` | 影响审核、学习、维护任务 |
| `视图配置` | 只影响当前页面显示 |
| `任务配置` | 只影响后台任务执行 |
| `危险操作` | 会删除、合并、重建、覆盖数据 |
| `只读诊断` | 不改变状态 |

所有配置块必须显示：

```text
影响范围
生效时机
是否持久化
是否需要重启
回滚方式
```

## 7. 页面优化需求

## 7.1 总览仪表盘 `/dashboard`

当前已有：

- 记忆总量。
- 标签覆盖率。
- 社交认知。
- 数据库体积。
- 注入趋势。
- 模块 token 排行。
- 系统健康。
- 最近错误。

优化：

1. 增加“能力状态矩阵”：

| 能力 | 状态 | 管理入口 |
|---|---|---|
| 高级检索 | ok/degraded/off | `/explore` |
| BookLore | ok/degraded/off | `/blackbox/book-lore` |
| FewShot | ok/degraded/off | `/blackbox/fewshot` |
| Facts | ok/degraded/off | `/blackbox/facts` |
| 人物画像/好感 | ok/degraded/off | `/blackbox/people` |
| FTS5 | ok/degraded/off | `/blackbox/indexes` |
| 注入 Trace | ok/degraded/off | `/injection` |
| 通道配置 | ok/degraded/off | `/channels` |

2. 增加“需要处理”卡片：

- 无标签记忆数量 -> `/import`。
- Tag 低覆盖 -> `/maintenance`。
- BookLore 索引缺失 -> `/blackbox/book-lore`。
- FewShot 待审候选 -> `/blackbox/fewshot`。
- 注入通道错误 -> `/injection`。
- 配置校验失败 -> `/channels`。

3. 模块 token 排行支持点击跳转：

- `book_lore_tokens` -> BookLore 管理。
- `fewshot_tokens` -> FewShot 管理。
- `jargon_tokens` -> 黑话页。
- `belief_tokens` -> 信念页。
- `facts_tokens` -> Facts 管理。

4. 最近错误卡片支持：

- 按服务筛选。
- 复制错误。
- 跳转相关页面。

## 7.2 记忆管理器 `/memories`

当前已有：

- 搜索。
- source / sender / has_tags / has_vector 筛选。
- 详情抽屉。
- 修改 source、sender_name、group_id。
- 删除、批量删除、re-embed。
- 记忆星云聚类。

优化：

1. source 类型语义化：

| source | 页面文案 | 处理方式 |
|---|---|---|
| `live` | 群聊长期记忆 | 保持在记忆管理器 |
| `bzz_experience` | 第一人称经历 | 链接到灵魂/经历视图 |
| `book_lore` | 书设知识 | 提示去 BookLore 管理 |
| `bot_reply` | Bot 回复素材 | 可送入 FewShot 候选 |
| `fewshot` | 风格范例 | 提示去 FewShot 管理 |

2. 详情抽屉增加关联区：

- Tags。
- Facts。
- Beliefs。
- Person links。
- Injection traces。
- Similar memories。

3. 批量操作分危险等级：

- `re-embed`: 中风险。
- `改 source`: 中风险。
- `删除`: 高风险，必须二次确认。

4. 增加“转为管理对象”入口：

- Bot 回复 -> FewShot 候选。
- 世界观内容 -> BookLore 条目候选。
- 稳定关系句子 -> Fact 候选。

5. 星云视图降级为只读可视化，不和神经云图职责冲突。

## 7.3 智能导入 `/import`

当前已有：

- provider 配置保存。
- 外部插件数据源扫描与导入。
- LLM Tag 提取。
- SSE 进度与日志。

优化：

1. 页面拆成向导：

```text
配置检查 -> 数据源发现 -> 导入预览 -> 执行导入 -> Tag 提取 -> 结果复核
```

2. provider 配置块标识为：

```text
静态配置 / 需要重启 / 影响导入和 Tag 提取
```

3. 导入前必须有 dry-run 预览：

- 数据源。
- 总条数。
- 已导入估计。
- 重复估计。
- 将写入 source 类型。
- 是否会 re-embed。

4. SSE 控制台统一任务模型：

```json
{
  "task_id": "...",
  "task_type": "import | tag_extract",
  "status": "running | done | error | stopped",
  "progress": 0.5,
  "processed": 100,
  "total": 200,
  "errors": 0,
  "message": "..."
}
```

5. 中止按钮只对可中止任务显示。

6. 结果复核提供跳转：

- 去记忆管理器看新导入数据。
- 去维护工作台看 Tag 审计。
- 去总览看覆盖率变化。

## 7.4 注入观测台 `/injection`

当前已有：

- trace 列表。
- group/sender/bot/channel/status/error/scope/limit 筛选。
- trace 详情抽屉。

优化：

1. channel 筛选改为下拉：

```text
全部 | safety | memory | timeline | facts | persona | belief | jargon | fewshot | book_lore | fts5 | affinity
```

2. trace 列表增加：

- 命中通道数。
- 跳过通道数。
- 错误通道数。
- 主 token 消耗通道。

3. trace 详情增强阅读结构：

```text
请求上下文
通道瀑布
命中项
过滤项
最终注入文本
错误/警告
反馈与修正入口
```

4. 每个通道命中项提供跳转：

- memory item -> `/memories?id=...`。
- belief -> `/beliefs?id=...`。
- jargon -> `/jargon?id=...`。
- fewshot -> `/blackbox/fewshot?id=...`。
- book_lore -> `/blackbox/book-lore?id=...`。
- facts -> `/blackbox/facts?id=...`。

5. 保持观测台定位：

```text
观测和验证，不承载对象本体管理。
```

## 7.5 通道热配置 `/channels`

当前已有：

- 加载当前通道配置。
- 编辑 enabled / priority / top_k / max_items / token_budget / timeout_ms / min_score。
- 校验预览。
- 应用配置。
- 恢复默认。
- diff 展示。
- safety channel 不可关闭。

优化：

1. 每个通道行增加说明：

| 通道 | 说明 | 管理入口 |
|---|---|---|
| safety | 身份污染、近期去重、安全兜底 | 无，固定启用 |
| memory | 群聊长期记忆召回 | `/memories` |
| timeline | 时间线/近期重要事件 | `/soul` 或 `/blackbox/people` |
| facts | 事实关系注入 | `/blackbox/facts` |
| persona | 人格画像摘要 | `/soul` |
| belief | 信念注入 | `/beliefs` |
| jargon | 黑话理解参考 | `/jargon` |
| fewshot | 风格范例注入 | `/blackbox/fewshot` |
| book_lore | 书设知识注入 | `/blackbox/book-lore` |
| fts5 | 全文检索补召回 | `/blackbox/indexes` |
| affinity | 好感/关系信号 | `/blackbox/people` |

2. 每个字段加解释：

| 字段 | 说明 |
|---|---|
| enabled | 是否参与注入 |
| priority | 通道执行/拼接优先级 |
| top_k | 检索类通道候选数 |
| max_items | 非检索类通道最多注入条目 |
| token_budget | 单通道预算 |
| timeout_ms | 单通道超时 |
| min_score | 检索命中最低分 |

3. 增加风险提示：

- 关闭 `memory`：长期记忆不注入。
- 关闭 `facts`：稳定事实关系不注入。
- 关闭 `belief`：Bot 判断/认知不注入。
- 关闭 `fewshot`：风格示例不注入。
- 关闭 `book_lore`：书设知识不注入。
- 调低 token_budget：可能丢关键信息。
- 调低 timeout：可能导致慢通道被跳过。

4. diff 卡片必须按通道聚合，不只按 path 列表。

5. 应用后提供跳转到 `/injection` 验证最近 trace。

## 7.6 维护工作台 `/maintain` 或 `/maintenance`

当前 `/maintain` 是静态 Tag 维护工作台。

v4.5.0 目标：升级为完整维护工作台。

页面分区：

```text
说明区
任务区
任务配置区
建议处理区
事件区
危险区
```

### 7.6.1 说明区

必须说明：

- 维护工作台用于清理 Tag、关系、索引与任务状态。
- 不直接生成新人格。
- 不直接改变 AstrBot Persona。
- 审计任务默认只生成建议。
- 批准建议可能修改数据库。
- 删除/合并/重建属于危险操作。

### 7.6.2 任务区

任务清单：

| 任务 | 类型 | 风险 |
|---|---|---|
| Tag 质量审计 | 生成建议 | 低 |
| Tag 合并建议 | 生成建议/批准后改 DB | 中 |
| Tag 重分类建议 | 生成建议/批准后改 DB | 中 |
| Tag 删除建议 | 生成建议/批准后改 DB | 高 |
| 孤立 Tag 检查 | 只读诊断 | 低 |
| 低质量关系检查 | 只读/生成建议 | 中 |
| 重复记忆检查 | 只读/生成建议 | 中 |
| 向量索引健康检查 | 只读诊断 | 低 |
| FTS5 索引健康检查 | 只读诊断 | 低 |
| BookLore 索引检查 | 只读诊断 | 低 |
| FewShot 健康检查 | 只读诊断 | 低 |
| EPA basis 重建 | 任务执行 | 中 |

### 7.6.3 任务配置区

字段：

- `strategy`
- `scan_limit`
- `confidence_threshold`
- `dry_run`
- `generate_suggestions_only`
- `batch_size`
- `timeout_seconds`
- `event_retention_days`

每个字段必须解释影响范围。

### 7.6.4 建议处理区

每条建议展示：

- action。
- 目标对象。
- 证据。
- 生成原因。
- 预期影响。
- 是否可回滚。
- 批准后执行动作摘要。

### 7.6.5 事件区

展示：

- 任务 ID。
- 任务类型。
- 状态。
- 开始/结束时间。
- 耗时。
- 处理数量。
- 生成建议数量。
- 错误原因。

### 7.6.6 危险区

必须二次确认：

- 批量删除 Tag。
- 批量合并 Tag。
- 重建索引。
- 清空维护建议。
- 清理历史 trace。

## 8. 黑盒管理前端矩阵

## 8.1 BookLore 管理

新页面：

```text
/blackbox/book-lore
```

定位：

```text
世界观/书设知识库，不是群聊记忆，不是人格指令。
```

功能：

- 概览：实体数、关系数、社区数、notes 数、索引数、更新时间。
- 列表：book_entities、book_communities、book_relations、book_notes。
- 搜索：关键词搜索 + 向量测试召回。
- 详情：title/name、summary/description、source_book、relations、vector 状态。
- 索引健康：HNSW 文件是否存在、id map 是否存在、count 是否匹配。
- 操作：重建索引、禁用条目、删除条目、导入/刷新。
- 测试：输入 query，只查 BookLore，显示命中和分数。

需要后端 API：

```text
GET  /api/blackbox/book-lore/summary
GET  /api/blackbox/book-lore/entities
GET  /api/blackbox/book-lore/communities
GET  /api/blackbox/book-lore/relations
POST /api/blackbox/book-lore/search
POST /api/blackbox/book-lore/reindex
PATCH /api/blackbox/book-lore/entities/:id
DELETE /api/blackbox/book-lore/entities/:id
```

## 8.2 FewShot 管理

新页面：

```text
/blackbox/fewshot
```

定位：

```text
风格范例库，不是事实记忆，不代表真实发生过。
```

功能：

- 概览：pending / approved / rejected 数量、平均 score、最近提取时间。
- 列表：content、score、traits、status、bot_id、created_at、approved_at。
- 筛选：status、bot_id、trait、score range。
- 操作：批准、拒绝、禁用、删除、编辑、新增。
- 候选提取：触发 `FewShotService.extract_candidates()`，展示候选。
- 漂移检测：输入近期回复，运行 `check_drift()`。
- 测试匹配：模拟某 bot_id 会注入哪些 few-shot。

需要后端 API：

```text
GET  /api/blackbox/fewshot/summary
GET  /api/blackbox/fewshot/examples
POST /api/blackbox/fewshot/extract
POST /api/blackbox/fewshot/drift-check
POST /api/blackbox/fewshot/test-injection
PATCH /api/blackbox/fewshot/examples/:id
DELETE /api/blackbox/fewshot/examples/:id
```

## 8.3 Facts / 关系管理

新页面：

```text
/blackbox/facts
```

定位：

```text
稳定事实关系与人物/实体关系，不是自由文本记忆。
```

功能：

- facts 列表：subject、predicate、object、fact_type、confidence、source_memory_id。
- 过滤：fact_type、subject、object、confidence、source。
- 详情：证据记忆、更新时间、关联 tag。
- 操作：编辑 confidence、归档、删除、合并重复 facts。
- PERSON_ALIAS 专区：展示昵称/别名分流结果。
- 测试：输入当前消息，查看 facts channel 会注入什么。

需要后端 API：

```text
GET    /api/blackbox/facts
GET    /api/blackbox/facts/:id
PATCH  /api/blackbox/facts/:id
DELETE /api/blackbox/facts/:id
POST   /api/blackbox/facts/test-injection
```

## 9. 后端 API 原则

1. 管理页 API 使用 `/api/blackbox/*` 前缀。
2. 只读接口先行，写操作分期实现。
3. 写操作必须返回：

```json
{
  "ok": true,
  "changed": 1,
  "warnings": [],
  "rollback_hint": "..."
}
```

4. 危险操作必须支持 preview：

```text
POST /merge-preview
POST /rebuild-preview
```

5. 所有列表接口支持：

```text
limit
offset
search
sort
filter
```

6. API 不得依赖前端猜字段；字段名与 DB/服务层保持文档化映射。

6. 页面 loading / error / empty 状态必须完整。
