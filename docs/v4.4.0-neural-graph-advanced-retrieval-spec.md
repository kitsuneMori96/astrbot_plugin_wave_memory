# v4.4.0 Neural Graph / Advanced Retrieval Spec

v4.4.0 聚焦神经云图与高级检索拆分。它把现有 `/explore` 3D 星图从“看图谱”升级为“调试高级检索链路”的实验台。

## 1. 版本边界

前置版本：

- v4.2.2 已修复 React WebUI 与后端契约错位。
- v4.3.0 已处理 Jargon / Holyman / 注入治理，并明确神经云图进入 v4.4.0。

本版本只处理：

1. 神经云图页面的信息结构、配置分层与交互体验。
2. 高级检索链路拆分展示：EPA、残差金字塔、脉冲传播、测地线重排、向量召回、最终分数解释。
3. `/api/query` 调试接口与 `kg.js` 查询入口的契约修复。
4. 图谱视图配置、查询配置、任务/事件状态的去混淆。

本版本不处理：

- 不重做 React 主 WebUI 全部页面。
- 不新增 BookLore / FewShot / Facts / PersonRegistry 等管理页面；这些进入 v4.5.0。
- 不重复做注入观测台；已有 `/injection` trace 功能只在 v4.5.0 做体验优化。
- 不迁移所有静态页面到 React。
- 不改变高级检索算法本身的数学目标，只补齐可见化、可控性和契约。

## 2. 当前事实

### 2.1 后端已有能力

`engine/query_engine.py` 当前完整检索管线：

```text
query embedding
  -> EPA 聚焦度分析
  -> 残差金字塔 tag 分层命中
  -> 脉冲传播 energy_field
  -> tag context vector 融合
  -> memory vector search
  -> 时间衰减 / importance / access boost
  -> 测地线重排
  -> min_similarity 过滤
  -> final top_k
```

相关模块：

- `engine/epa.py`: `EPAModule.analyze()` 返回 `logic_depth`、`entropy`、`dominant_axis`。
- `engine/residual_pyramid.py`: `ResidualPyramid.analyze()` 返回 `levels`、`coverage`、`final_residual`。
- `engine/spike_routing.py`: `SpikeRouter.propagate()` 返回 `activated_tags`、`energy_field`。
- `engine/geodesic_rerank.py`: `GeodesicReranker.rerank()` 返回重排后的候选，含 `geo_score`。
- `engine/query_engine.py`: `_wave_boost()` 串联 EPA / 残差金字塔 / 脉冲传播 / 向量融合。

### 2.2 WebUI 当前问题

`webui/blueprints/memories.py::query_test()` 当前读取：

```python
enable_spike = body.get("enable_spike", True)
enable_pyramid = body.get("enable_pyramid", True)
enable_epa = body.get("enable_epa", False)
enable_geodesic = body.get("enable_geodesic", False)
```

但实际调试路径只完整处理：

- 基础 memory vector search。
- 简化版 spike routing。
- geodesic rerank。

缺口：

- `enable_pyramid` 被读取但未执行残差金字塔。
- `enable_epa` 被读取但未执行 EPA。
- spike seed 直接从 `tag_index.search()` 取，不走残差金字塔结果。
- debug payload 只有计数，没有每阶段明细。
- geodesic 没有返回 L0/L1/L2 降级、geo_score、前后排名对比。
- 最终分数没有拆开 similarity、importance、time_decay、access_boost、geodesic_boost。

`webui/static/kg.js` 语义搜索入口当前硬编码：

```json
{
  "enable_spike": true,
  "enable_pyramid": false,
  "enable_epa": false,
  "enable_geodesic": false
}
```

这导致神经云图入口实际上没有展示完整高级检索能力。

### 2.3 配置混淆

`explore.html` 当前同时存在：

- 顶部/左上：图谱配置。
- 玩具台：布局模式、节点大小、边权、流速。
- 右下：legend / 控制指引。
- 查询入口：隐藏在不同模式下。

问题：

- 视图配置和查询配置混在一起。
- 用户无法判断哪些配置影响机器人运行，哪些只影响画布显示。
- 右下角区域承担 legend、任务、事件、状态提示，语义不清。

## 3. 目标

1. 神经云图支持完整高级检索实验：基础向量、EPA、残差金字塔、脉冲传播、测地线重排可单独开启/关闭。
2. 每次查询返回可解释的阶段结果，而不是只有最终记忆列表。
3. 图谱上能高亮：seed tag、残差层 tag、spike emergent tag、参与测地线重排的记忆。
4. UI 明确区分：视图配置、查询配置、运行配置、事件状态。
5. `/api/query` 调试契约稳定，可被 React WebUI、静态神经云图、测试脚本复用。
6. 高级检索异常必须降级展示原因，不得静默失败。

## 4. 非目标

- 不新增 BookLore 管理页。
- 不新增 FewShot 管理页。
- 不新增 Facts / PersonRegistry / Affinity 管理页。
- 不重写注入观测台。
- 不把维护工具完整迁移到 React；维护工具系统化进入 v4.5.0。
- 不修改 AstrBot 静态配置机制。

## 5. 高级检索阶段契约

新增或扩展调试接口：

```text
POST /api/query
```

请求：

```json
{
  "text": "查询文本",
  "top_k": 12,
  "group_id": "可选",
  "source_filter": "可选",
  "exclude_sources": ["可选"],
  "debug": true,
  "stages": {
    "epa": true,
    "pyramid": true,
    "spike": true,
    "geodesic": true,
    "shotgun": false,
    "svd_dedup": false
  },
  "params": {
    "pyramid_max_levels": 3,
    "pyramid_top_k": 10,
    "spike_max_hops": 4,
    "spike_firing_threshold": 0.1,
    "geodesic_alpha": 0.3
  }
}
```

响应：

```json
{
  "results": [],
  "timing": {},
  "debug": {
    "query": {},
    "embedding": {},
    "epa": {},
    "pyramid": {},
    "spike": {},
    "vector_search": {},
    "scoring": {},
    "geodesic": {},
    "final": {},
    "warnings": []
  }
}
```

要求：

- `debug` 字段只在 `debug=true` 时返回完整明细。
- 任一阶段不可用时必须返回：`enabled=false` 或 `available=false`、`reason`。
- 阶段异常不得中断整次检索；写入 `warnings` 并降级。

## 6. 阶段明细

### 6.1 Embedding

返回：

```json
{
  "available": true,
  "dimension": 1024,
  "latency_ms": 123.4
}
```

失败：

```json
{
  "available": false,
  "reason": "embedding failed"
}
```

### 6.2 EPA

执行条件：

```text
stages.epa=true AND c.epa exists AND c.epa.initialized=true
```

返回：

```json
{
  "enabled": true,
  "available": true,
  "logic_depth": 0.72,
  "entropy": 0.28,
  "dominant_axis": 3,
  "interpretation": "focused",
  "latency_ms": 1.2
}
```

解释规则：

| 条件 | interpretation |
|---|---|
| `logic_depth >= 0.66` | `focused` |
| `logic_depth <= 0.33` | `diffuse` |
| 其他 | `mixed` |

### 6.3 残差金字塔

执行条件：

```text
stages.pyramid=true AND c.residual_pyramid exists
```

返回：

```json
{
  "enabled": true,
  "available": true,
  "coverage": 0.61,
  "levels": [
    {
      "level": 0,
      "residual_energy_ratio_before": 1.0,
      "tags": [
        {"tag_id": 1, "name": "角色", "type": "person", "similarity": 0.82}
      ]
    }
  ],
  "all_tag_ids": [1, 2, 3],
  "latency_ms": 8.5
}
```

要求：

- `tag_id` 必须补齐 `name`、`tag_type`，避免 UI 再额外 N 次查询。
- 每层最多展示 `pyramid_top_k` 个 tag。
- UI 展示每层 residual 变化，不只展示最终 coverage。

### 6.4 脉冲传播

执行条件：

```text
stages.spike=true AND c.spike_router exists AND c.cooccurrence.node_count > 0
```

seed 来源优先级：

```text
pyramid tags -> tag_index direct hits -> empty
```

返回：

```json
{
  "enabled": true,
  "available": true,
  "seed_tags": [
    {"tag_id": 1, "name": "角色", "weight": 0.82, "source": "pyramid.level_0"}
  ],
  "activated_tags": [
    {"tag_id": 2, "name": "事件", "energy": 0.42, "is_emergent": true}
  ],
  "energy_field_size": 54,
  "energy_field_top": [
    {"tag_id": 2, "name": "事件", "energy": 0.42}
  ],
  "params": {
    "max_hops": 4,
    "firing_threshold": 0.1,
    "base_decay": 0.25,
    "wormhole_decay": 0.7,
    "tension_threshold": 1.0
  },
  "latency_ms": 6.1
}
```

可选增强：

- 如果实现成本可控，增加 `hops` 数组展示每跳传播结果。
- 如果 hop 数据过大，只返回 top N 并提供 `truncated=true`。

### 6.5 Vector Search

返回：

```json
{
  "candidate_count": 48,
  "top_candidates": [
    {"memory_id": 1, "distance": 0.21, "similarity": 0.79}
  ],
  "used_vector": "fused | raw",
  "fusion": {
    "alpha": 0.3,
    "tag_count": 12,
    "context_vector_norm": 1.0
  },
  "latency_ms": 4.4
}
```

要求：

- 当高级阶段产出 tag context vector 时，标记 `used_vector=fused`。
- 当没有 matched tags 或 total_weight 为 0 时，标记 `used_vector=raw` 与原因。

### 6.6 Scoring

每条候选返回分数拆分：

```json
{
  "memory_id": 1,
  "similarity": 0.79,
  "importance": 1.2,
  "time_decay": 0.98,
  "access_boost": 1.15,
  "score_before_geodesic": 1.07,
  "source": "live",
  "is_cross_group": false
}
```

要求：

- UI 最终结果卡片显示“为什么排在这里”。
- 相似度过滤前后的数量必须可见。

### 6.7 测地线重排

执行条件：

```text
stages.geodesic=true AND c.geodesic exists AND energy_field not empty
```

返回：

```json
{
  "enabled": true,
  "available": true,
  "mode": "L0 | L1 | L2",
  "alpha": 0.3,
  "min_geo_samples": 4,
  "reranked": [
    {
      "memory_id": 1,
      "rank_before": 5,
      "rank_after": 2,
      "score_before": 0.71,
      "score_after": 0.86,
      "geo_score": 0.8,
      "hit_count": 5
    }
  ],
  "latency_ms": 3.3
}
```

降级规则：

| 模式 | 条件 | UI 文案 |
|---|---|---|
| L0 | 有候选满足 `hit_count >= min_geo_samples` | 完整测地线重排 |
| L1 | 有 energy hits 但无 L0 样本 | 简化能量重排 |
| L2 | 无 energy_field、无候选或异常 | 跳过重排 |

`GeodesicReranker` 当前没有显式返回 mode，需要新增 debug-only 计算或包装层。

## 7. 神经云图 UI 改造

### 7.1 面板分层

神经云图页面必须分成四类区域：

| 区域 | 影响范围 | 示例 |
|---|---|---|
| 视图配置 | 只影响当前画布 | 节点数、边权阈值、布局、图层 |
| 查询配置 | 只影响本次实验查询 | EPA/Pyramid/Spike/Geodesic 开关、top_k |
| 运行提示 | 只读展示真实运行状态 | EPA 是否初始化、cooccurrence 节点数 |
| 事件状态 | 最近操作/任务/错误 | 查询耗时、阶段 warning、加载失败 |

视图配置必须显示 badge：

```text
仅当前视图，不影响机器人回复
```

查询配置必须显示 badge：

```text
仅本次实验查询，不写入运行配置
```

### 7.2 查询实验台

新增“高级检索实验台”面板：

- 查询输入框。
- 模式 preset：
  - `baseline`: 只跑基础向量。
  - `spike`: 基础向量 + 脉冲传播。
  - `pyramid`: EPA + 残差金字塔 + 脉冲传播。
  - `full`: EPA + 残差金字塔 + 脉冲传播 + 测地线。
  - `ablation`: 同一 query 并行跑 baseline/full，对比排名变化。
- top_k。
- source filter。
- debug 开关。

### 7.3 阶段结果面板

查询后展示 tabs：

```text
总览 | EPA | 残差金字塔 | 脉冲传播 | 向量召回 | 测地线 | 最终结果 | Warning
```

每个 tab 展示：

- 是否启用。
- 是否可用。
- 耗时。
- 输入/输出摘要。
- 失败/降级原因。

### 7.4 图谱高亮

图谱节点高亮规则：

| 数据 | 样式 |
|---|---|
| query seed tag | 紫色外环 |
| pyramid level 0/1/2 | 分层色带 |
| spike emergent tag | 脉冲光晕 |
| geodesic promoted memory | 金色边框 |
| geodesic demoted memory | 灰色虚线 |
| final result memory | 高亮实体卡 |

点击节点后右侧详情显示：

- 所属阶段。
- 分数。
- 来源阶段。
- 相关 memory/tag。
- 可跳转到记忆详情。

### 7.5 右下角状态区

右下角只负责：

- legend。
- 最近事件。
- 最近 warning。
- 查询总耗时。

右下角不得承载运行配置和查询配置。
