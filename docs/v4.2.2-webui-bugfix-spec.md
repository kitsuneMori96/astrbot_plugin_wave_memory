# v4.2.2 WebUI Bugfix Spec

WaveMemory React WebUI 与后端契约修复方案。只修已确认的接口/字段错位与黑话误学习边界，不重构新版产品信息架构。

## 1. 范围

### 必修 Bug

1. Beliefs 前后端契约错位
   - 前端仍使用 `self | other | world | value`。
   - 后端与 DB 已使用 `self_identity | person_judgment | world_view | preference`。
   - 前端字段名 `confidence/timestamp/last_reinforced` 与后端 `strength/created_at/updated_at` 不一致。
   - 批量审核响应字段存在 `approved_count/deleted_count` 与前端展示字段错位风险。

2. Jargon 前后端契约错位
   - 列表查询前端传 `page/size`，后端接收 `limit/offset`。
   - 证据查询前端调用 `/api/jargon/:id/evidence`，后端实际是 `/api/jargon/:id/context`。
   - 批量接口前端路径偏 REST 嵌套：`/batch/review`、`/batch/delete`；后端实际是 `/batch-review`、`/batch-delete`。
   - 全局启用切换存在 `toggle-global` 与 `toggle_global` 命名差异风险。

3. 黑话误学习与噪声污染
   - 高频昵称、群友简称、英文代码词、普通词被误判为黑话候选。
   - 当前过滤更像“事后补救”，没有在候选生成前建立候选类型分类。
   - 已拒绝/噪声条目混入本地黑话管理主列表，导致用户误以为系统正在学习 `object/get/from/has` 等无意义 token。

### 目标

- WebUI 点击、分页、审核、证据查看不再 404 或错页。
- 信念类型在前端、API、DB、文案上统一。
- 黑话候选先分类，再进入 LLM 推断；昵称/代码词默认不进入黑话表。
- 已确认黑话与待审核候选、拒绝噪声、人物称呼分区展示。

## 2. 根因与修复项

### 2.1 Beliefs 契约修复

改动点：

- `webui/frontend/src/lib/api.ts`
  - `BeliefType` 改为后端真实枚举：`self_identity | person_judgment | world_view | preference`。
  - 请求 payload 使用 `strength`，不再提交 `confidence`。
  - 响应适配 `created_at/updated_at/reinforcement_count`，兼容旧字段但内部统一新字段。
  - 批量结果读取 `approved_count/deleted_count`，前端显示层不再猜字段。

- `webui/frontend/src/pages/BeliefsPage.tsx`
  - tab、筛选、文案改为“自我身份 / 人物判断 / 世界观 / 偏好”。
  - 删除 `self/other/world/value` 的硬编码。
  - 新建/编辑表单默认使用 `self_identity`。

兼容规则：

- 后端可临时接受旧类型并映射到新类型，但新增数据只写新枚举。
- 前端显示未知类型时标记为 `未知类型`，不静默归入某个分类。

### 2.2 Jargon API 契约修复

改动点：

- `webui/frontend/src/lib/api.ts`
  - `listJargons({ page, size })` 转换为 `limit=size&offset=(page-1)*size`。
  - `getJargonEvidence(id)` 改为调用 `/api/jargon/${id}/context`。
  - 批量审核改为 `/api/jargon/batch-review`。
  - 批量删除改为 `/api/jargon/batch-delete`。
  - 全局切换统一后端路径 `/api/jargon/${id}/toggle_global`。

- `webui/blueprints/jargon.py`
  - 可选增加 alias 兼容旧前端路径，避免用户缓存旧 bundle 后直接 404。
  - GET 列表兼容 `page/size`，但内部标准化为 `limit/offset`。
  - context 响应字段稳定为 `anchor/context_before/context_after/fallback`。

验收：

- 黑话列表第 1/2 页不重复、不错位。
- 点击证据弹窗返回上下文，不出现 404。
- 批量通过、拒绝、删除能显示正确计数。

### 2.3 黑话误学习修复

新增候选分类层：

- `local_jargon`: 群内专属表达，需要上下文解释。
- `global_catchphrase`: 广域网络口癖/梗，如 Holyman 类表达。
- `cultural_label`: 文化角色标签或抽象称呼，如用户提到的“嘉豪”“龟男”一类，必须有语义证据，不能按人名简单丢弃。
- `person_alias`: 群友昵称、QQ 昵称、称呼、用户名。
- `technical_noise`: `object/get/from/has/id/json` 等代码或系统 token。
- `ordinary_word`: 普通词、短词、无语义高频词。

处理规则：

- `person_alias/technical_noise/ordinary_word` 默认不进入 `jargon_entries` 主表。
- `local_jargon/global_catchphrase/cultural_label` 才允许进入待审核候选。
- LLM 推断 prompt 必须输出 `candidate_type + reason + safety_note`，不能只回答“是不是黑话”。
- 高频词不能单独作为黑话证据，必须满足“语义偏移/反常搭配/重复上下文/群内解释需求”之一。
- 已拒绝噪声进入 blocklist 或 noise log，不在默认黑话主列表展示。

后端改动点：

- `services/jargon/candidate_miner.py` 或等价候选生成模块：先做规则分类，再调用 LLM。
- `services/jargon/llm_validator.py` 或等价 LLM 推断模块：扩展 prompt 与结构化返回。
- `webui/blueprints/jargon.py`：列表默认隐藏 rejected noise，支持 `include_rejected=true` 审计查看。

数据兼容：

- 不删除旧数据。
- 对历史 `rejected` 且明显技术噪声的记录加隐藏标记或迁移到 blocklist。
- `confirmed` 的历史词条保留，避免误删用户已审核资产。

## 3. 不在本轮处理

- 不重写整个 React WebUI 信息架构。
- 不调整 AstrBot 静态 Persona 主权边界。
- 不把 WaveMemory 灵魂引擎改成覆盖 AstrBot Persona 的人格系统。
- 不在本轮解决完整的“心智中心/信念工坊/Prompt 总账”产品重构。
- 不把广域黑话改成强制模仿器；运行时仍只作为理解与氛围辅助。
- 不直接修改 `AstrBot-master/data/plugins/astrbot_plugin_wave_memory/` 运行时目录。

## 4. 验证清单

### 4.1 静态检查

- `python -m compileall astrbot_plugin_wave_memory`
- `python -c "import ast, pathlib; [ast.parse(p.read_text(encoding='utf-8')) for p in pathlib.Path('astrbot_plugin_wave_memory/webui/blueprints').glob('*.py')]"`
- `npm run lint`
- `npm run build`

### 4.2 单元/契约测试

- 新增或更新 Beliefs API 契约测试：类型枚举、创建、批量审核、列表字段。
- 新增或更新 Jargon API 契约测试：分页、context 证据、batch-review、batch-delete、toggle_global。
- 新增黑话候选分类测试：昵称、代码 token、普通词不进主表；文化标签与广域口癖进入待审。

### 4.3 运行时验证

- 同步到运行时目录前先完成开发目录测试。
- 重启 AstrBot 容器后检查日志无 WebUI blueprint 报错。
- 浏览器验证：信念页筛选正常；黑话页分页、证据弹窗、批量操作正常。
- 抽样导入/挖掘聊天记录，确认昵称与 `object/get/from/has` 类 token 不再污染本地黑话主列表。

## 5. 后续讨论议题

- 心智中心、信念工坊、语言词典、记忆库、Prompt 总账、通道配置属于下一轮产品重构设计。
- AstrBot Persona 继续作为系统级宪法；WaveMemory 本轮不尝试覆盖 AstrBot Persona。
- 广域黑话要重新定义为“文化口癖/反串表达资产”，不是单纯词典，也不是身份指令。
