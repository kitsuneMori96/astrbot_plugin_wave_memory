# WaveMemory v1.3.0 — 改进方向 Spec

## 来源：竞品分析 + VCP 浪潮算法 + 群友反馈

核心原则：**不加外部依赖**，用现有 SQLite + HNSW + jieba + 已有的 VCP 模块实现。

---

## 一、记忆检索质量（解决"不记事"）

### 1.1 FTS5 精确召回通道

**问题**：向量检索搜"北老师"/"张雪峰"时语义相似的噪音太多，精确人名被淹没。
**方案**：inject_memory 加一个 FTS5 通道（已有 `_setup_fts5()`），与向量结果合并去重。
**逻辑**：
```
message → jieba 分词 → FTS5 MATCH → 取 top 10
向量 top_k → 合并 FTS5 结果 → 去重 → 最终 top_k
```
**优先级**：P0
**改动**：main.py inject_memory 加 `_ch_fts5()` 通道，~20 行

### 1.2 facts 图遍历（1-2 跳关联）

**问题**：有人说"北老师"，facts 搜到"■■■■ 群友称呼为 北老师"，但搜不到关于■■■■的其他 facts。
**方案**：facts 通道命中后，从命中实体沿 facts 三元组再走 1 跳。
**逻辑**：
```
keyword match facts → 命中实体 A
→ SELECT * FROM facts WHERE subject=A OR object=A LIMIT 3
→ 一起注入
```
**优先级**：P1
**改动**：main.py _ch_facts() 扩展，~15 行

### 1.3 高级检索模块确认生效

**问题**：spike/pyramid/epa/geodesic 刚开启，需要确认 cooccurrence 矩阵已构建。
**验证**：检查 `cooccurrence.forward` 非空，tag_index 有数据。
**优先级**：P0（观察）

## 二、实时知识提取（解决"反应慢"）

### 2.1 Bot 回复后即时 facts 提取

**问题**：consolidation 每 4h 才跑，群友纠正 bot 后 4h 内 bot 仍然不知道。
**方案**：在 `after_message_sent` hook 中，如果 bot 回复包含事实性断言（"xxx是xxx"/"xxx死了"等），即时写 facts。
**逻辑**：
```
bot_reply 包含 "是/死了/出生于/位于/属于" 等模式
→ 正则提取 subject-predicate-object
→ db.insert_fact() + importance 提权对应记忆
```
**优先级**：P1
**改动**：main.py on_bot_sent 扩展，~30 行

### 2.2 被纠正后自动提权

**问题**：SelfReflect 写入 importance=1.5，在 10.5 万条里仍被淹没。
**方案**：纠正学习产出 → importance=3.0 + 写入 facts 表。
**优先级**：P0
**改动**：services/self_reflect.py，2 行

## 三、MetaThinking 改造（解决"不自然"）

### 3.1 共享上下文 + AstrBot 人格

**问题**：MetaThinking 独立调 LLM，自带硬编码 prompt，不读 AstrBot 系统人格。导致判断与实际回复风格脱节。
**方案**：
- MetaThinking 的 system prompt 从 AstrBot 配置的人格 prompt 中提取
- MetaThinking 结果（tone/action）注入主对话上下文，而非独立调两次 LLM
- 或者：合并为一次 LLM 调用，在系统提示里加"先思考再回复"结构

**备选方案（推荐）**：
```
不再单独调 MetaThinking LLM，改为在主对话 system_prompt 中注入：
[内部思考指令]
在回复前先在心里想一下：
- 这个人是谁？（好感度、印象、标签见上方）
- 此刻你对他什么感觉？
- 你想怎么回？（正常/冷淡/怼/不理）
然后直接按你的判断回复，不要输出思考过程。
```
这样零额外 LLM 调用，人格一致性自动保证。

**优先级**：P0（架构变更，需仔细设计）
**改动**：大改 meta_thinking_check hook

### 3.2 对话对象推断（规则链）

**问题**：MetaThinking 每条消息都调 LLM 判断是否该回复，token 消耗大。
**方案**（学自 context_aware）：纯规则前置过滤：
```
1. @bot → 必须回复
2. 引用了 bot 消息 → 必须回复
3. bot 刚回复此人(30s内) → 连续对话，回复
4. 包含兴趣关键词 + 没在跟别人说话 → 可能插话
5. 其他 → 不回复（跳过 MetaThinking LLM）
```
**优先级**：P1
**改动**：main.py meta_thinking_check 前加规则判断，~30 行

## 四、好感度驱动行为（解决"态度不对"）

### 4.1 好感度等级化行为差异

**问题**：好感度 80 和 20 的人收到差不多的回复。
**方案**：persona 注入中的"态度指令"更具体：
```
好感 < -20：敌意，可以直接怼/无视
好感 -20~20：陌生人，礼貌但冷淡
好感 20~50：熟人，正常交流
好感 50~80：朋友，可以开玩笑/用昵称
好感 > 80：亲密，主动关心/撒娇/可以损
```
**优先级**：P1（已有基础，persona_evolution 里有 ATTITUDE_INSTRUCTIONS）
**改动**：services/persona_evolution.py 优化注入文本

### 4.2 沉默倒计时 + 主动问候

**方案**（学自 proactive_chat）：
- 高好感用户 3 天没说话 → bot 主动问候
- 群里冷场 30 分钟 + bot 有关切话题 → 主动说话
- 连续主动 3 次没人理 → 停止

**优先级**：P2
**改动**：新增 proactive scheduler，~80 行

## 五、黑话主动使用（解决"不会说黑话"）

### 5.1 注入格式改为词汇表

**问题**：当前注入 `<jargon>br的意思是HTML换行</jargon>`，bot 理解了但不用。
**方案**：改为：
```
[你的群内词汇]
以下是这个群常用的表达方式，你可以自然地使用它们：
- "塔菲" = 虚拟主播雏草姬
- "团群" = 跑团群
- "donk" = CS2 职业选手
在合适的场景下，你可以主动用这些词而不是标准说法。
```
**优先级**：P1
**改动**：services/jargon/service.py get_injection() 改格式，~10 行

## 六、绰号自动学习

### 6.1 Consolidation prompt 加绰号提取

**问题**：consolidation 的 social 字段只提取"人际关系"，不提取"谁的绰号是什么"。
**方案**：prompt 加一条：
```
- nickname: [{"person": "QQ号或昵称", "called": "群友给他起的绰号/代称"}]
```
提取后写入 facts + person_registry aliases。

**优先级**：P2
**改动**：services/consolidation.py prompt + 写入逻辑，~20 行
