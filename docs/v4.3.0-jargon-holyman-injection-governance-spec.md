# v4.3.0 Jargon / Holyman / Injection Governance Spec

v4.3.0 只优化现有黑话、Holyman 广域参考、注入观测与通道治理；不做 WebUI 大改版，不包含神经云图。神经云图优化单独进入 v4.4.0。

## 1. 版本边界

v4.3.0 接在 v4.2.2 止血修复之后。

前置条件：

- v4.2.2 已修复 Beliefs 前后端契约错位。
- v4.2.2 已修复 Jargon 分页、context 证据、批量操作接口错位。
- v4.2.2 已建立黑话候选基础分流字段：`candidate_type`、`reject_reason`、`source_context`。

本版本只处理：

1. 本地群聊黑话候选进入系统前的分流规则。
2. Holyman-skills 广域文化资产的全量学习、分层展示和 reference-only 注入边界。
3. 注入观测台对黑话/Holyman 命中、跳过、过滤原因的解释。
4. 现有黑话页、注入观测台、通道热配置页的小幅优化。

本版本不迁移导航，不重命名现有页面，不新增大型产品模块。

## 2. 目标

1. 本地黑话学习不再把群友昵称、简称、QQ 昵称、普通高频词、技术 token 当成黑话候选。
2. LLM 只审核“可能是黑话/口癖/暗语”的候选，不承担所有明显噪声分类。
3. Holyman-skills 作为广域口癖和抽象文化参考库全量学习：短语、概念、例句、原始语料、候选、屏蔽项和 manifest 都保留。
4. Holyman 运行时只作为理解参考，不改变系统身份、不注入人格指令、不作为 few-shot 风格样本。
5. 注入观测台能解释黑话/Holyman：命中了什么、来源是哪一层、为什么注入、为什么跳过。
6. 现有 WebUI 只做最小体验修复：默认隐藏已分流昵称/噪声，保留审计入口。

## 3. 非目标

- 不包含神经云图优化；神经云图进入 v4.4.0。
- 不新增心智中心、语言词典、Prompt 总账等新版导航。
- 不重排现有 React WebUI 侧边栏。
- 不把关切、欲望、情绪包装成本版本能力。
- 不改变 AstrBot Persona 主权边界。
- 不让 Holyman-skills 覆盖 bot 人格。
- 不删除历史数据；历史噪声只做隐藏、标记、迁移预览，不默认物理删除。

## 4. 本地黑话候选治理

## 4.1 当前问题

现有 `JargonService.mine()` 已有 `_should_filter_candidate()`、`_is_person_like_candidate()` 和 `candidate_type`，但规则仍偏弱：

- 群友昵称、简称、历史 display name 可能进入黑话候选。
- `object/get/from/has/json/id` 等技术 token 可能因高频进入候选。
- LLM 否决不等于设计正确；明显非黑话不应进入 LLM 审核阶段。
- `person_alias_diverted` 被写成 rejected 后，如果默认列表仍展示，会造成“系统在学昵称黑话”的错觉。

## 4.2 候选路由顺序

候选进入 LLM 前必须先经过本地路由：

```text
raw candidate
  -> known_person_alias?
  -> technical_noise?
  -> ordinary_word?
  -> holyman_reference_hit?
  -> local_jargon_candidate
```

处理规则：

| 路由结果 | 写入 | 默认黑话列表 | LLM 审核 |
|---|---|---|---|
| `person_alias` | `facts.fact_type=PERSON_ALIAS`；可选保留 rejected audit row | 隐藏 | 否 |
| `technical_noise` | rejected audit 或 blocklist | 隐藏 | 否 |
| `ordinary_word` | 丢弃或 rejected audit | 隐藏 | 否 |
| `holyman_reference_hit` | 不写成本地黑话；使用 Holyman 参考层 | Holyman 分区展示 | 否 |
| `local_jargon_candidate` | `jargon.status=pending/confirmed/rejected` | 展示 | 是 |

## 4.3 person alias 判定

除现有正则外，增加数据驱动判定：

- 命中 `memories.sender_name` 历史集合。
- 命中 `user_profiles.nickname`。
- 命中 `person_registry.display_name`，若表存在。
- 命中 `facts.fact_type='PERSON_ALIAS'` 的 subject/object。
- 候选和 source message 的 `sender_id` 或 `sender_name` 强相关。

命中后：

- 调用现有 `_record_person_alias_fact()` 写 `PERSON_ALIAS` fact。
- `jargon` 表若保留审计行，必须设置：
  - `candidate_type='person_alias'`
  - `status='rejected'`
  - `is_jargon=0`
  - `reject_reason='person_alias_diverted'`
- 默认列表隐藏这些审计行。

## 4.4 technical noise 判定

默认过滤：

- 纯英文 API/代码词：`object`、`get`、`from`、`has`、`json`、`id`、`type`、`value`、`data`。
- URL、路径、文件扩展名、JSON key、日志字段。
- 纯数字、版本号、hash 片段。
- 过短普通英文 token，除非命中 Holyman allowlist。

## 4.5 本地黑话 LLM 审核

只有 `local_jargon_candidate` 进入 `_llm_validate_candidates()` 和 `JargonInferenceEngine.infer()`。

LLM prompt 继续要求排除：

- 普通词。
- 昵称/人名。
- 品牌名。
- 无上下文词。

LLM 失败继续 fail-closed：不新增 confirmed 黑话。

## 5. Holyman 广域参考库

## 5.1 定位

Holyman-skills 是广域抽象文化、口癖、反串表达和语料参考源。v4.3.0 不另造一套文化标签模型，直接尊重现有 Holyman 分层资产。

核心原则：

```text
全量学习，不影响人格。
```

含义：

- 全量学习：同步并保留 Holyman-skills 的短语、概念、例句、语料、候选、屏蔽项、manifest、quality report。
- 不影响人格：不把 Holyman 内容注入系统身份、不覆盖 AstrBot Persona、不作为 few-shot 风格样本、不要求 bot 模仿 Holyman 说话。

## 5.2 分层资产

继续使用现有分层：

| 层 | 来源 | 用途 | runtime_match |
|---|---|---|---|
| `phrases` | curated/core + 安全短语 | 用户显式命中时解释 | 允许 |
| `concepts` | Holyman skill 知识章节 | WebUI 查看、理解参考 | 默认否 |
| `examples` | quotes / communication | 证据与例句展示 | 默认否 |
| `corpus` | 神言原始语料 | 全量检索、审计、候选来源 | 否 |
| `candidates` | 从 corpus 生成 | 人工审核 | 否 |
| `blocked` | 本地屏蔽 | 匹配保护 | 否 |
| `manifest` | 同步来源 | 版本与完整性校验 | 否 |

## 5.3 运行时匹配

运行时规则：

- 只在用户消息显式包含已允许 runtime match 的短语时注入解释。
- 注入文本必须保留安全头：仅供理解、不改变系统身份、不要求模仿或主动使用。
- `concepts/examples/corpus` 可以作为 WebUI 参考和候选来源，但不能自动变成 confirmed runtime phrase。
- `blocked` 命中必须跳过。

## 5.4 Holyman 与本地黑话关系

- Holyman 命中是广域参考，不写成本地群黑话 confirmed 记录。
- 如果同一词在本地群聊产生独特含义，才允许作为本地黑话候选进入 LLM 审核。
- 本地黑话页必须区分 `source='wave_memory'` 和 `source='holyman_skills'`。
- Holyman 同步继续使用预览确认流程，不允许列表加载时直接写入。

## 5.5 WebUI 展示要求

现有黑话页保留，Holyman 区块展示：

- 本地版本 / 远端版本。
- 同步状态 / 更新时间 / warning。
- phrases、concepts、examples、corpus、candidates、blocked 数量。
- quality_report 错误项。
- manifest 文件列表。
- 每个资产的 `reference_only`、`runtime_match`、`source`。

## 6. 注入观测与通道治理

## 6.1 注入边界

Jargon 注入继续通过现有 `JargonInjector` / `JargonChannel` 完成。

必须保持：

- 只解释用户消息中已经出现的词。
- 不用释义相似度触发。
- 不主动联想未出现的黑话。
- 不注入身份或风格指令。
- identity contamination 过滤继续生效。

## 6.2 注入观测台增强

现有注入观测台需要能解释 jargon channel：

每个命中 item 至少展示：

```json
{
  "word": "v我50",
  "meaning": "...",
  "source": "holyman_skills | wave_memory",
  "source_layer": "phrases | local",
  "reference_only": true,
  "runtime_match": true,
  "matched_by": "explicit_user_message",
  "preview": "v我50 → ..."
}
```

跳过/过滤时展示：

- `no matching confirmed jargon`
- `jargon service is unavailable`
- `identity_contamination`
- `reference_only_non_runtime_layer`
- `candidate_diverted_person_alias`
- `technical_noise_filtered`

## 6.3 通道热配置

不新增大配置页，只在现有通道配置中确保 jargon channel 可见：

- enabled。
- priority。
- token_budget。
- max_items / max_inject。
- status / last_latency_ms / last_hit_count。

不新增“主动使用 Holyman 风格”开关。Holyman 不作为人格或风格通道。

## 8. 数据契约

## 8.1 `jargon` 表

复用现有字段：

- `candidate_type`
- `reject_reason`
- `source_memory_id`
- `source_message_ts`
- `source_sender_id`
- `source_context`
- `source`
- `scope`
- `status`

推荐 `candidate_type` 值：

```text
jargon                 兼容旧值/未分类本地候选
local_jargon           本地群聊黑话候选
person_alias           人物昵称/简称分流
technical_noise        技术 token/代码噪声
ordinary_word          普通高频词
holyman_reference_hit  命中 Holyman 广域参考
```

兼容规则：

- 旧 `NULL` 或 `jargon` 视为本地候选。
- confirmed 历史记录不自动降级。
- rejected person_alias/noise 默认隐藏但保留审计。

## 8.2 `facts` 表

人物别名分流继续写：

```text
subject = sender_id
predicate = alias_or_name
object = candidate word
fact_type = PERSON_ALIAS
source_memory_id = matched memory id
confidence = 0.6 默认
```

本版本不设计人物画像 UI；该数据供后续 v4.4.0 使用。

## 8.3 Holyman 资产

继续维护：

```text
assets/holyman/phrases.json
assets/holyman/concepts.json
assets/holyman/examples.json
assets/holyman/corpus.json
assets/holyman/candidates.json
assets/holyman/blocked.json
assets/holyman/manifest.json
```

DB 分层表继续由 `upsert_jargon_knowledge_snapshot()` / `replace_jargon_knowledge_table()` 同步。

## 9. 实施分期

## 9.1 Phase 1：候选路由增强

- 增强 person alias 数据集合：sender_name、user_profiles.nickname、person_registry、PERSON_ALIAS facts。
- 增强 technical noise / ordinary word 过滤。
- Holyman 命中改为 reference hit，不写成本地 confirmed。
- 补充单元测试。

## 9.2 Phase 2：黑话页默认隐藏分流噪声

- 默认列表排除 person_alias / technical_noise / ordinary_word rejected rows。
- 增加审计开关查看隐藏项。
- 保留批量处理能力。

## 9.3 Phase 3：Holyman 全量参考展示强化

- 确认 phrases/concepts/examples/corpus/candidates/blocked/manifest/quality report 都可见。
- 增强 reference-only 文案。
- 保留预览确认同步流程。

## 9.4 Phase 4：注入观测台解释增强

- jargon channel item 补 source/layer/reference_only/matched_by。
- filtered 列表补具体原因。
- trace 详情展示黑话安全头和命中来源。

## 10. 验收清单

## 10.1 功能验收

- 群友昵称、简称、历史 display name 不进入默认黑话列表。
- `object/get/from/has/json/id` 等技术 token 不进入默认黑话列表。
